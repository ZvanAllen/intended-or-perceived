# Deviations and decisions

## November 14, 2026

- The original 24-clip pilot used `P3.txt`. The main-run plan specifies `P3-v2.txt`, which asks for raw JSON without fences and an explicit check that the six percentages sum to 100. Raw pilot responses and strict scoring are preserved. Live validation reached 23/24 for OpenAI and 24/24 for Gemini. One OpenAI request lost its connection before an HTTP response. The SDK error did not trigger the retry classifier on that run, so the cell was kept as a request error and the reservation was retained. The classifier now also checks for a ledger entry with an ambiguous outcome and no HTTP status when the SDK provides no usable error type. Offline tests cover this path.
- The two-model audio diagnostic uses the pilot clips at their original level for transcription and peak-adjusted copies for a forced-choice check. The gain copies use a single linear gain per clip to target −1 dBFS and preserve the original sample rate. These are diagnostic calls outside the main study. See `results/AUDIO_DIAGNOSTIC.md` for outcomes and the distinction between the original and adjusted audio.
- The budget code sizes new reservations to a checked request envelope and retains the project-wide US$25 cap. It uses 64 audio tokens per second, twice Google’s published audio estimate, plus 0.1 seconds and 16 audio tokens for framing. For text input it reserves one token per UTF-8 byte plus 128 framing tokens. Output is capped at 256 tokens. These are conservative working assumptions, verified against settled usage with a stop if usage exceeds the bound. The original unresolved reservation for ledger call 69 remains intact. Cumulative exposure from both audio diagnostics and P3-v2 validation is capped separately at US$0.50. A bounded retry is available for connection failures, HTTP 429 and HTTP 5xx. The transcript flags retried cells and preserves failed outcomes. [Gemini audio documentation](https://aistudio.google.com/docs/audio#technical-details)
